## Mục đích

Thống nhất thiết kế tầng kiến trúc **Abstract class `Account` và `User`** dùng chung cho 3 trang web (CellphoneS, GitHub, Steam), phục vụ **Login page** và **Profile User page**.

---

## Nội dung thảo luận & quyết định

### 1. Phân tích yêu cầu login & profile của 3 web gốc

**Quyết định:** Xác định nguyên tắc tách trách nhiệm — `Account` phục vụ **đăng nhập**, `User` phục vụ **hiển thị profile**.

**Lý do:** Mỗi web đăng nhập bằng thứ khác nhau, nhưng profile thì đều hiển thị tên và avatar. Tách hai lớp thì phần chung mới dùng chung được.

| Web | Đăng nhập bằng |
|---|---|
| CellphoneS | Số điện thoại |
| GitHub | Username / Email |
| Steam | Account name |

### 2. Thuộc tính & method dùng chung cho cả 3 web

**Quyết định:** Abstract chỉ chứa phần **cả 3 web đều có**.

- `Account`: `accountId`, `password`, `status`, `role`, `createdAt`, `lastLoginAt`
- `User`: `userId`, `displayName`

**Lý do:** Tránh nhồi thuộc tính riêng của từng web vào lớp cha; chỉ giữ phần dùng chung để 3 nhánh `extend` đồng bộ.

### 3. Các phương thức của `Account`

**Quyết định:** Chốt các method `setCreatedAt()`, `setLastLoginAt()`, `updateStatus(AccountStatus s)`, `getRole()`, `getStatus()`.

**Lý do:** Các thao tác về trạng thái tài khoản giống nhau ở cả 3 web, đưa vào abstract để dùng chung.

### 4. Phương thức của `User`

**Quyết định:** Chốt method `updateDisplayName(String name)`.

**Lý do:** `displayName` là trường hiển thị chung của cả 3 web; cập nhật tên hiển thị là thao tác phổ biến.

---

## Bản Abstract chốt tại cuộc họp

```java
public abstract class Account {
// properties
  String accountId;
  String password;
  String status;
  String role;
  Date   createdAt;
  Date   lastLoginAt;

// methods
  Getter / Setter
  setCreatedAt()
  setLastLoginAt()
  updateStatus(AccountStatus s)
  getRole()
  getStatus()
}

public abstract class User {
// properties
  String userId;
  String displayName;

// methods
  Getter / Setter
  updateDisplayName(String name)
}
```

## Điểm cần làm rõ sau cuộc họp

> Phần này **không phải nội dung họp**, ghi lại để 3 nhóm xác nhận trước khi triển khai.

1. **Bản Abstract đang lưu hành khác biên bản này.** Bản các nhóm nhận về có `Account { accountId, password, role, isLogin(), login() }` và `User { userId, accountId, displayName }` — không có `status`, `createdAt`, `lastLoginAt`; `User` thì có thêm `accountId`. Cần xác nhận đây là bản sửa **sau** cuộc họp hay là ghi nhầm, và cập nhật lại một trong hai.
2. **Chưa có cầu nối giữa `Account` và `User`** trong bản ghi tại họp. Bản đang lưu hành cho `User` giữ `accountId` — cần chốt chính thức để 3 nhóm cùng một chiều.
3. **`AccountStatus` chưa liệt kê giá trị cụ thể.** Nếu 3 nhóm tự đặt giá trị khác nhau thì abstract mất tác dụng.
4. **`role` chưa xác định kiểu và tập giá trị.**
5. **Chưa có method abstract nào** ở cả hai lớp. Đề bài yêu cầu 3 Class Detail "tuân thủ Abstract" — cần ít nhất một điểm bắt lớp con override, nếu không thì không có gì để tuân thủ.
6. **Chưa chốt cách giả lập `abstract` và `private` trong JavaScript** — sản phẩm nộp là HTML/CSS/JS, mà JS không có hai từ khoá này.
